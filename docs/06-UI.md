# 06 — UI (UI Toolkit)

## 1. Setup

- `UiRoot` (MonoBehaviour on `UI` object) creates at runtime:
  ```csharp
  var ps = ScriptableObject.CreateInstance<PanelSettings>();
  ps.themeStyleSheet = Resources.Load<ThemeStyleSheet>("Hexhaven/UI/Theme");
  ps.scaleMode = PanelScaleMode.ScaleWithScreenSize;
  ps.referenceResolution = new Vector2Int(1920, 1080);
  ps.screenMatchMode = PanelScreenMatchMode.MatchWidthOrHeight;
  ps.match = 1f;                                  // match height
  ps.scale = settings.UiScale;                    // 0.8–1.4
  ps.sortingOrder = 10;
  var doc = gameObject.AddComponent<UIDocument>();
  doc.panelSettings = ps;
  doc.visualTreeAsset = Resources.Load<VisualTreeAsset>("Hexhaven/UI/Root");
  ```
- `Theme.tss` content: `@import url("unity-theme://default");` (one line).
- `Root.uxml` references `Tokens.uss` and `Common.uss` via `<Style src="...">` and contains six full-screen layers in this order (later = on top), all `position: absolute; left/top/right/bottom: 0; picking-mode: Ignore` except when showing content:
  `#layer-world` (tooltips anchored to 3D), `#layer-hud`, `#layer-screens`, `#layer-dialogs`, `#layer-curtain`, `#layer-toasts`.
- Each screen/dialog is a `VisualTreeAsset` in `Resources/Hexhaven/UI/...` instantiated into its layer by a C# controller class (one class per uxml, in `Runtime/UI/...`), which queries elements by **name** (`root.Q<Button>("btn-roll")`). Names below are mandatory.
- **Pointer over UI:** `UiRoot.IsPointerOverUI(screenPos)` uses `panel.Pick(RuntimePanelUtils.ScreenToPanel(panel, new Vector2(x, Screen.height - y)))` and returns true if the picked element is not a layer root. Camera and board picking ignore input when true.
- All text from `Strings.cs`. All numbers update from `GameSession.Display` (display snapshot, see 02 §4 item 3 and §9).

### 3.5 Game Over (`Screens/GameOver.uxml`)
Full-screen dimmed overlay after the victory animation (2.5 s delay).
- `go-title`: "<Name> wins!" in their colour; `go-subtitle`: "11 points in 18 rounds".
- `go-table`: per player row: name, Outposts×1, Keeps×2, Monuments (revealed), Longest Path 2, Strongest Guard 2, **Total**; winner row highlighted.
- `go-stats` tabs: `tab-dice` (bar chart of DiceHistogram 2–12 with expected-value ghost bars, drawn with VisualElements as bars), `tab-resources` (per player Produced/Spent/Traded/Plundered/Discarded table), `tab-awards` (path lengths, wardens played).
- Buttons: `btn-rematch` (same config, new seed), `btn-new-setup` (→ New Game prefilled), `btn-title`.

### 4.1 Pass-device curtain (`Dialogs/Curtain.uxml`, `#layer-curtain`)
Active when the config has ≥ 2 human seats. Whenever the **human who needs to act next** differs from the human who last saw the screen (turn change, discards, incoming offers, victim choice by another human, etc.):
- Full-screen opaque panel in that player's colour (darkened), text "Pass to <Name>", emblem, `btn-curtain-ready` "I'm <Name> — show my hand".
- The board stays visible behind a 70 % dark scrim; hand bar, charter panel and private log lines are hidden until ready is pressed.
- During bot turns the HUD shows **no** private hand (only public info) when ≥ 2 humans.

## 5. Phase prompts (`tb-prompt`) and interaction modes

| Phase / state | Prompt (viewer is acting human) | Board interaction |
|---|---|---|
| RollForOrder | "Roll to decide who goes first" + `btn-roll` | none |
| SetupOutpost | "Place your first/second outpost" | corner markers (legal setup corners); click places immediately |
| SetupPath | "Place a path next to your outpost" | edge markers |
| TurnStart | "Roll the dice (or play a Warden first)" | none |
| Discard | "Waiting for players to discard…" (if not affected) | none |
| MoveStorm | "Move the Storm to a new tile" | tile markers |
| ChooseVictim | "Choose who to plunder" | candidate buildings highlighted; dialog |
| Main | "Build, trade, or end your turn" | depends on mode: Path/Outpost/Keep markers after pressing a build button |
| RoadCrew | "Road Crew: place a free path (n left)" | edge markers |
| Not acting | "<Name> is …" (rolling / building / trading / thinking) | hover tooltips only |

Placement modes: pressing a build button toggles the mode; clicking a legal marker submits the action and exits the mode (Path mode stays active if the player can afford another Path and a legal edge exists — "chain building"; Esc/right-click exits). Clicking an illegal spot shows a toast with the reason (`Strings.Errors[code]`).

## 6. Log (Chronicle) formatting

One line per significant event, with `<color>` rich text names and resource icons as coloured letters. Examples:
- "**Bryn** rolled **8** (5 + 3)." / "Harvest: **You** +2 Grain, **Corra** +1 Timber."
- "**Dain** built an Outpost." / "**You** raised a Keep."
- "Storm surge! **Corra** discarded 4 cards (2 Clay, 2 Iron)."
- "**Bryn** moved the Storm to the Mine (6) and plundered **You** (Iron)." — for third parties: "…plundered **You** (a card)."
- "**Corra** bought a Charter." / "**Corra** played a Warden." / "Decree: **Dain** took 5 Grain (You 2, Bryn 3)."
- "**You** traded 1 Iron for 1 Grain with **Bryn**." / "**Dain** traded 4 Timber to the harbor for 1 Clay."
- "**Bryn** now holds the Longest Path (6)." / "The Longest Path is set aside."
- Production lines are merged per roll; shortage: "Bank short of Grain — nobody harvests Grain."

## 9. Toasts & tooltips
- Toasts: bottom-centre above hand bar, max 3 stacked, 2.5 s, fade. Types: info (dim), error (danger border), success (ok border). Used for illegal action reasons, "Autosaved", "Trade completed", award changes for the viewer, "Bank short of Grain".
- Tooltips: on hover over buttons with reasons/costs, resource cards (name + count + harbor rate), player cards (full breakdown visible info), bank chips. 0.35 s delay.

## 11. Accessibility & polish checklist
- All interactive elements reachable by mouse; key shortcuts shown as `.kbd` pills in tooltips.
- Minimum text size 13 px at 1080p reference; contrast ≥ 4.5:1 for body text on panels.
- Emblems make every player distinguishable without colour.
- Every disabled button explains why on hover.
- Never block the player with an animation longer than 2.5 s; clicking anywhere during bot animations speeds the EventPlayer ×3 for the current event.
