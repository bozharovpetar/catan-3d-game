# 04 — AI (Hexhaven.Core.AI)

Bots live in Core so they run in the headless harness. They see only what R-13 allows: the board, public state, their own hand/charters, and the public event stream (card counting via `CardTracker`).

## 1. API

```csharp
namespace Hexhaven.Core.AI
{
    public sealed class BotParams
    {
        public BotDifficulty Difficulty;
        public double Noise;                  // random jitter added to scores
        public int SetupTopK;                 // choose uniformly among top K setup sites
        public bool ProposesDomesticTrades;
        public int MaxProposalsPerTurn;
        public int MaxMaritimePerTurn;
        public double AcceptThreshold;        // min utility gain to accept a trade
        public int RefuseLeaderAtVp;          // refuse trades with players whose public VP >= this; int.MaxValue = never
        public bool UsesCardTracker;
        public bool UsesLookahead;
        public bool KeepsHandUnderLimit;
        public static BotParams For(BotDifficulty d, int victoryTarget);   // implemented in scaffold
    }

    public static class BotBrain
    {
        /// Returns a legal action for `seat`, which must be in engine.AwaitingInput().
        /// Must never return an action that fails Validate (tested over 10k games).
        public static GameAction Decide(GameEngine engine, int seat, BotMemory memory);
    }

    /// Per-bot persistent memory across decisions (owned by the driver, one per bot seat).
    public sealed class BotMemory
    {
        public BotMemory(int seat, int playerCount);
        public readonly int Seat;
        public CardTracker Tracker;           // fed every public/visible event
        public int ProposalsThisTurn, MaritimeThisTurn, TurnSeen;
        public int LastRejectedTradeHash;     // avoid re-proposing an identical offer in the same turn
        public void Observe(GameEvent e, GameState s);   // called by driver for every event (redacted for this seat)
    }
}
```

The driver (sim harness or `BotDriver`) creates one `BotMemory` per bot seat, calls `memory.Observe(evt.RedactFor(seat), state)` for **every** event in order, and when a bot seat is in `AwaitingInput()` calls `Decide`. The RNG for noise: `new Pcg32((ulong)(uint)(Seed * 1000003 + seat * 7919 + State.ActionLog.Count))`.

### 1.1 Parameters per difficulty

| Param | Easy | Normal | Hard |
|---|---|---|---|
| Noise (score jitter, uniform ±) | 2.0 | 0.4 | 0.1 |
| SetupTopK | 5 | 2 | 1 |
| ProposesDomesticTrades | no | yes | yes |
| MaxProposalsPerTurn | 0 | 2 | 3 |
| MaxMaritimePerTurn | 2 | 4 | 6 |
| AcceptThreshold | −0.5 | 0.0 | 0.6 |
| RefuseLeaderAtVp (target − n) | never | target − 2 | target − 3 |
| UsesCardTracker | no (Decree random) | yes | yes |
| UsesLookahead | no | no | yes (1-ply evaluation of **deterministic build actions only** — BuildPath/Outpost/Keep on a clone; never RollDice, BuyCharter, MoveStorm/plunder or anything that draws from `Rng`/`Deck`, since the clone would reveal hidden future information, R-13.3) |
| Keeps hand ≤ 7 at end of turn when possible | no | yes | yes |

## 2. Shared evaluation (`BotEvaluator`)

### 2.1 Resource weights
`boardPips[r]` = Σ pips of tiles producing r. `meanPips = Σ boardPips / 5`.
`scarcity[r] = clamp(meanPips / max(boardPips[r], 1), 0.75, 1.6)`.
Phase weights (multiply): early game (player VP < 4): Timber 1.15, Clay 1.15, Fiber 1.0, Grain 1.0, Iron 0.85; late (VP ≥ 4): Timber 0.9, Clay 0.9, Fiber 1.0, Grain 1.15, Iron 1.2.
`w[r] = scarcity[r] × phase[r]`.

### 2.2 Production profile
`prod[s][r]` = Σ over buildings of seat s on tiles producing r of pips × (1 Outpost / 2 Keep), with Storm tile counted at 0.

### 2.3 Site value `SiteValue(v, s)` (for an open vertex)
```
value = Σ_{tiles t of v producing r} pips(t) × w[r] × (t == Storm ? 0.4 : 1)
      + 1.2 × (# resource types at v that s currently produces 0 of)
      + harborBonus
      + 0.8 if v's tiles include both Timber and Clay producers (early game only)
      + 0.6 if v's tiles include both Grain and Iron producers (late game only)
      − 0.5 × (# tiles of v that are Ruins or off-board/ocean)  // coastal corners have fewer tiles
harborBonus: specific 2:1 of resource r: 2.5 × min(1, prod[s][r] / 6) + 0.5; Generic: 1.0 + 0.1 × Σ prod[s]; (setup round 1: halve harborBonus)
```

### 2.4 Hand utility `Utility(hand, s)`
Goals considered (in this order of preference when legal/possible): Keep (if s has an Outpost and Keeps left), Outpost (if a legal site exists with ignoreCost, or reachable in ≤ 2 Paths), Charter (deck non-empty), Path.
`need` = sum of the two highest-priority available goals' costs (component-wise max of their costs, not sum).
```
U = Σ_r [ 2.0 × min(hand[r], need[r]) + 0.4 × w[r] × max(0, hand[r] − need[r]) ]
    − (hand.Total > 7 ? 0.6 × (hand.Total − 7) : 0)             // 7-risk, weighted by P(7)=1/6 already folded in
```

### 2.5 Turns-to-afford estimate `Eta(cost, s)`
For each r with deficit d_r = max(0, cost[r] − hand[r]): expected per-turn income `inc_r = prod[s][r] / 36 × N` (N = players: you get production on every roll), floored at 0.05; `eta_r = d_r / inc_r`. `Eta = max_r eta_r` (0 if affordable).

## 3. Decisions by phase

### 3.1 RollForOrder / RollDice
Always roll (except Warden-before-roll logic below).

### 3.2 Setup outpost
Score every legal setup vertex with `SiteValue` + noise; for round 2 add `+0.7 ×` (number of resource types newly covered compared with round-1 outpost) and `+0.5` if the two outposts' numbers are different (diversifies rolls). Pick uniformly among the top `SetupTopK`.

### 3.3 Setup path
Among legal edges, pick the one whose far vertex maximises `FrontierValue(far, s)`:
`FrontierValue(v) = max(IsOpenSite(v) ? SiteValue(v) : 0, 0.75 × max over neighbours n of v with IsOpenSite(n) of SiteValue(n))`, −5 if v holds an opponent building. Avoid edges pointing into the sea when equal (prefer edges with 2 tiles).

### 3.4 TurnStart (before rolling)
Play a Warden first if `CanPlayCharter(Warden)` and any of:
- the Storm sits on a tile where s has buildings with Σ pips ≥ 4;
- playing it would take or secure Strongest Guard (`WardensPlayed + 1 >= 3` and `> holder's`), or win the game via that award;
- Hard only: the leader (highest public VP, not s) has ≥ target − 2 VP and a legal Storm tile hits them.
Otherwise `RollDice`.

### 3.5 Discard
Remove cards one at a time, each time choosing the card whose removal minimises the utility loss `U(hand) − U(hand − 1·r)` (ties: discard the resource with the highest count, then lowest w). Easy: same but with Noise.

### 3.6 MoveStorm
Score each legal tile t:
```
score(t) = Σ_{opponent buildings b on t} (b is Keep ? 2 : 1) × pips(t) × (1 + VP_pub(owner)/target) × (owner has cards ? 1.2 : 1)
         − 10 × Σ_{own buildings on t} (b is Keep ? 2 : 1)
         + 0.5 if t has at least one plunder candidate
```
Pick max (+ noise). If every score ≤ 0, pick a tile with no buildings at all, preferring Ruins, else the lowest-pip tile (never the current tile).

### 3.7 ChooseVictim
Highest public VP; ties → most cards; ties → seat order after s. Hard: if CardTracker knows a candidate surely holds a resource s needs for its top goal, add +1 to that candidate's ranking score before comparing.

### 3.8 Main — one action per call, priority list
Recompute everything each call. The first applicable rule returns its action.

1. **Open trade handling (proposer):** if `ActiveTrade` is ours: if any Accepted/Countered response exists whose terms are acceptable (`Utility gain ≥ 0` for Countered and the bot can pay the counter's Give; Accepted always), `ConfirmTrade` with the best one (highest utility gain; ties lowest seat); else `CancelTrade` (this also covers the defensive case of being called while responses are still Pending — never fall through to other rules while our offer is open). Drivers ask responders first, so normally all responses are in.
2. **Win now:** if any single legal action reaches the victory target (Keep, Outpost, Path giving Longest Path, Warden giving Strongest Guard, Charter purchase can't be predicted → skip), do it.
3. **Keep:** if a Keep is affordable, build it on the Outpost with the highest production (pips Σ, Storm-free).
4. **Outpost:** if affordable and legal, build on the best `SiteValue` site.
5. **Road Crew:** if playable and (no legal outpost site with ignoreCost, or Longest Path contestable within 2 paths), play it; then in RoadCrew phase place free paths by the Path rule (7).
6. **Bounty:** if playable and it makes Keep or Outpost affordable (choose the 2 missing resources; if only 1 missing, also the most-needed next), play it.
7. **Path:** if affordable and any of:
   - no legal outpost site exists (ignoreCost) but a site is reachable within 2 edges → build the edge that maximises `FrontierValue` of its far end;
   - Longest Path: `PathLength + 1 > holderLength` (or reaching 5 when no holder) and the edge extends the longest trail;
   - hand.Total ≥ 8 and nothing better is affordable (avoid 7-risk).
   Never spend Timber/Clay on a Path if that makes an Outpost that was affordable-after-one-trade unaffordable.
8. **Decree:** if playable: Normal/Hard use `CardTracker.EstimatedTotal(r)` over opponents; play on the r maximising `estimated × (need[r] > hand[r] ? 1.5 : 1)` if that estimate ≥ 3. Easy: play on a random resource when holding it ≥ 2 turns.
9. **Charter:** buy if affordable and (no Outpost/Keep goal has Eta ≤ 2, or hand.Total ≥ 8, or Strongest Guard contestable). Hard: also buy if `Fiber+Grain+Iron` surplus beyond Keep need.
10. **Domestic trade proposal** (if ProposesDomesticTrades and ProposalsThisTurn < Max): build an offer toward the top goal: `Get` = 1 of the most-needed missing resource; `Give` = 1 (or 2 if Normal/Hard holds ≥ 3 surplus) of the resource with the largest surplus beyond `need`. Targets = all opponents except those with public VP ≥ RefuseLeaderAtVp. Skip the proposal if `Give` would be empty (no surplus), if the target mask would be 0, or if identical to `LastRejectedTradeHash` this turn. Increment `ProposalsThisTurn`.
11. **Maritime trade** (if MaritimeThisTurn < Max): for the top goal with the smallest Eta, if one maritime trade (or a sequence the bot can already afford) makes it affordable this turn, trade the surplus resource with the best rate for the missing resource. Easy: only 4:1 when hand.Total ≥ 8.
12. **Hand-limit dump** (Normal/Hard): if hand.Total > 7, do any affordable build/charter/maritime that reduces total; else nothing.
13. **EndTurn.**

### 3.9 RoadCrew phase
Place the free path maximising `max(FrontierValue(far end), longest-trail gain × 3)`.

### 3.10 RespondTrade (as target)
`gain = U(hand − offer.Get + offer.Give) − U(hand)` (from responder's perspective: they give offer.Get, receive offer.Give).
- Refuse (Declined) if proposer's public VP ≥ RefuseLeaderAtVp, or the trade would let the proposer immediately afford a VP build they couldn't before **and** proposer VP ≥ target − 3 (Hard only), or responder lacks the cards.
- Accept if gain ≥ AcceptThreshold.
- Hard/Normal counter: if gain < threshold but a counter exists where the proposer gives one more card of a resource they hold in surplus (by CardTracker estimate) making gain ≥ threshold, respond Countered with those terms (proposer perspective: Give + 1 of that resource, Get unchanged). The added resource must not appear in `Get` (R-9.2) and must be one the proposer actually holds per `CardTracker.KnownAtLeast` ≥ the new Give amount; otherwise Decline.
- Else Declined.

### 3.11 Bounty choice / Decree choice
Bounty: the 2 cards that maximise U after taking (respecting bank stock). Decree: §3.8 rule 8.

## 4. `CardTracker`

Tracks, for every opponent, a lower bound and an estimate of each resource in hand:
- `Produced`, `StartingResources`, `BountyTaken`, `DecreeResolved`, `MaritimeTraded`, `TradeCompleted`, `Discarded`: exact updates.
- `Built`, `CharterBought` (cost known): subtract cost.
- `Plundered` visible to us: exact; redacted: victim loses 1 unknown card → subtract proportionally from the victim's estimate (each resource × (1 − 1/total)); thief gains an unknown card → add the same proportions.
- Clamp at 0; when the known total (from public counts in state) disagrees, rescale the estimate to the true total.
API: `int KnownAtLeast(int seat, Resource r)`, `double Estimate(int seat, Resource r)`, `double EstimatedTotal(Resource r)` (over opponents).

## 5. Driver pacing (Runtime `BotDriver`, not Core)

| Situation | Delay before the bot acts |
|---|---|
| Roll-off roll, RollDice | 0.6 s × speed factor |
| Setup placement | 0.8 s |
| Build / buy / play | 0.7 s |
| Trade response | 0.6–1.4 s (uniform, per responder) |
| Bot proposer waiting for responses | `BotDriver` never calls `Decide` for a proposer while any target is still `Pending`; it waits until all targets have responded (human targets must answer — the incoming-offer dialog is modal and cannot be dismissed without a response). No timeout. |
| Discard | 0.5 s |
| End turn | 0.5 s |

Speed factor: Slow 1.6, Normal 1.0, Fast 0.4, Instant 0 (one action per frame). **Every** delay in this table, including trade-response delays, is multiplied by the speed factor. The driver never acts while the EventPlayer is still animating, so turns read clearly.

## 6. Quality bar (tested by the harness)

- 0 illegal actions over 10,000 4-bot games (mixed difficulties).
- ≥ 99.5 % of games finish before turn 400 (stalls must be rare; log seeds that don't).
- Mean game length 60–110 turns (15–28 rounds of 4).
- Win rate in 4-player games with 1 Hard + 3 Easy over 2,000 games: Hard ≥ 40 %. With 1 Normal + 3 Easy: Normal ≥ 33 %. Hard vs 3 Normal: Hard ≥ 28 %.
- Seat bias: no seat's win rate deviates from 25 % by more than 5 points over ≥ 2,000 all-Normal 4-player games (a 10,000-game run produces 2,000).
- Decide() mean time < 2 ms and 99.9th percentile < 30 ms (Hard lookahead included), measured after skipping the first 1,000 decisions of the process (JIT warm-up).
