## 2. Creating the Unity project (M0)

Preferred (Unity CLI, see the `unity-cli` skill):

```bash
unity --version                                   # CLI present?
unity editors --installed --format json           # find a 6000.0.x editor; install with: unity install lts --yes --accept-eula
unity templates list --editor lts --format json   # find the Universal 3D (URP) template id
unity projects create "game" --path . --editor-version lts --template <urp-3d-template-id>
```

If no Unity CLI/Editor is available to the agent, create the project folder structure by hand **only for text assets** (`Assets/…/*.cs`, `*.asmdef`, `*.uxml`, `*.uss`, `*.tss`, `Packages/manifest.json`) and rely on `tools/compile-check.sh` + `tools/sim/run-sim.sh` for verification; tell the user that Editor-side steps (scene creation, PlayMode tests, builds) must be run by them via `Hexhaven ▸ Setup Project` and the Test Runner (`Hexhaven ▸ Open Test Runner`, run EditMode then PlayMode).

## 4. Layering rules

```
           ┌──────────── Editor (menus, setup, screenshot) ───────────┐
           │                                                          │
  UI (UI Toolkit) ◄── GameSession ──► View (3D) ◄── EventPlayer       │
        ▲                 │  ▲                          ▲             │
        │                 ▼  │                          │             │
     Strings         GameEngine (Core) ──► GameEvent stream ─────────┘
                          ▲
                       BotBrain (Core.AI)
```

1. **Core** knows nothing about Unity. No `UnityEngine` usings, no `System.Random`, no `DateTime.Now`, no static mutable state, no threads. C# 7.2 syntax only (no records, no `init`, no switch expressions, no target-typed `new`, no `is not`, no ranges, no nullable reference annotations). All collections are `List<T>`/arrays/`Dictionary` with deterministic iteration (never iterate a `Dictionary`/`HashSet` to make a decision; use ordered lists).
2. **All state changes go through `GameEngine.Apply(GameAction)`**, which validates, mutates, appends to the action log and returns the produced `GameEvent`s. Nothing else mutates `GameState` (fields are public for reading/serialization convenience; treat as read-only outside the engine).
3. **Runtime/GameSession** owns the engine, forwards human and bot actions, and pushes events to the **EventPlayer**, which plays them sequentially as animations/sounds and only then lets the UI reflect the new state (the UI binds to a *display snapshot* updated by the EventPlayer as each event finishes, so numbers change in sync with animations).
4. **View** is a pure function of `GameState` + transient animations. `BoardView.SyncAll(state)` must be able to rebuild everything from state alone (used on load).
5. **UI** reads state via `GameSession.Display` (snapshot) and sends intents to `GameSession` (e.g. `session.SetMode(InteractionMode.PlacePath)` enters placement mode; `session.Submit(action)` applies).
6. **Bots** run in Core (`BotBrain.Decide(engine, seat)`), invoked by `BotDriver` (Runtime) with pacing delays; never on a background thread.

## 5. Determinism

- Single RNG: `Pcg32` stored in `GameState.Rng`; used for board generation, charter shuffle, roll-off, dice, plunder card selection. Nothing else.
- Bots use their own `Pcg32` seeded with `config.Seed * 1000003 + seat * 7919 + actionCount` per decision (so bot choices are reproducible but not part of the game RNG stream). Bot decisions are recorded as ordinary actions in the log, so replay does not need to re-run bots.
- Replay: `GameEngine.Replay(config, actions)` rebuilds identical state; `StateHasher.Hash(state)` (FNV-1a 64 over a canonical text dump, see 03-CORE-API §9) must match.

### 5.1 `Pcg32` (exact implementation — copy verbatim)

```csharp
namespace Hexhaven.Core
{
    /// <summary>PCG-XSH-RR 32-bit generator. Deterministic across platforms. State is fully serializable.</summary>
    public sealed class Pcg32
    {
        public ulong State;
        public ulong Inc;

        public Pcg32(ulong seed, ulong sequence = 54u)
        {
            State = 0UL;
            Inc = (sequence << 1) | 1UL;
            NextUInt();
            State += seed;
            NextUInt();
        }

        public uint NextUInt()
        {
            ulong old = State;
            State = unchecked(old * 6364136223846793005UL + Inc);
            uint xorshifted = (uint)(((old >> 18) ^ old) >> 27);
            int rot = (int)(old >> 59);
            return (xorshifted >> rot) | (xorshifted << ((-rot) & 31));
        }

        /// <summary>Uniform integer in [0, bound). Unbiased (rejection sampling).</summary>
        public int NextInt(int bound)
        {
            if (bound <= 0) throw new System.ArgumentOutOfRangeException("bound");
            uint b = (uint)bound;
            uint threshold = unchecked((uint)(-(int)b)) % b;
            while (true)
            {
                uint r = NextUInt();
                if (r >= threshold) return (int)(r % b);
            }
        }

        /// <summary>Uniform double in [0, 1).</summary>
        public double NextDouble() { return NextUInt() / 4294967296.0; }

        public int RollDie() { return NextInt(6) + 1; }

        public Pcg32 Clone() { var c = new Pcg32(0); c.State = State; c.Inc = Inc; return c; }

        /// <summary>Fisher–Yates shuffle, iterating from the end.</summary>
        public void Shuffle<T>(IList<T> list)
        {
            for (int i = list.Count - 1; i > 0; i--)
            {
                int j = NextInt(i + 1);
                T tmp = list[i]; list[i] = list[j]; list[j] = tmp;
            }
        }
    }
}
```
(add `using System.Collections.Generic;`). Seed conversion: `new Pcg32((ulong)(uint)config.Seed)`.

## 6. Scene composition & lifecycle

`Main.unity` contains only `HexhavenApp`. `HexhavenApp.Awake()`:
1. `Application.targetFrameRate = -1` (VSync governs); `QualitySettings.vSyncCount` from settings.
2. Load `SettingsStore` (PlayerPrefs JSON).
3. Create, as children of the app object: `Main Camera` (Camera + `CameraRig` + AudioListener; URP: `UniversalAdditionalCameraData` added automatically), `Sun` (directional light), `Fill` (second directional, no shadows), `World` (`BoardView`, `StormView`, `DiceView`, `OceanView`, `AmbientView`), `Audio` (`AudioService`), `UI` (`UIDocument` + `UiRoot`), `PostFX` (URP Volume, inside `#if HEXHAVEN_URP`).
4. Show the Title screen with a slowly orbiting preview board (BalancedRandom, random seed).

`HexhavenApp` also has `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)] EnsureApp()` that creates the app if the active scene has none (so pressing Play in an empty scene works).

`GameSession` lifecycle: `Start(config)` / `Load(saveText)` → per-frame `Tick(dt)` (BotDriver + EventPlayer) → `End()`. One session at a time.

## 7. Error handling & logging

- `Apply` never throws for illegal actions; it returns `ApplyResult.Fail(errorCode)`. It throws only on programmer errors (null action, corrupt state) — tests assert none occur.
- Runtime logs illegal human attempts at `Debug.Log` level with the error code (UI also shows a toast with the user-facing string from `Strings.Errors`).
- Invariant checks (`GameInvariants.Check`) run after every Apply in Editor/Development builds (`#if UNITY_EDITOR || DEVELOPMENT_BUILD`) and log `Debug.LogError` with the violation list.

## 8. Coding conventions

- Namespaces: `Hexhaven.Core`, `Hexhaven.Core.AI`, `Hexhaven` (runtime), `Hexhaven.UI`, `Hexhaven.EditorTools`, `Hexhaven.Tests`.
- Runtime/Editor: one public type per file. Core: closely related small types may share a file (the provided `scaffold/` groups them; keep or split, but keep the namespaces and signatures).
- No `FindObjectOfType` at runtime except in `EnsureApp`; pass references explicitly from `HexhavenApp`.
- No `Update()` on per-piece objects except animation helpers that self-destroy when done; tweens run through `Tweens` (a single MonoBehaviour updating a list).
- All user-facing strings in `Strings.cs` (static readonly fields / format methods).
- XML doc comment on every public type and member in Core.

## 9. Runtime flow (GameSession, EventPlayer, BotDriver)

```csharp
namespace Hexhaven
{
    public enum InteractionMode { None, PlacePath, PlaceOutpost, PlaceKeep, PlaceSetupOutpost, PlaceSetupPath, MoveStorm, PlaceFreePath }
    public enum PickKind { None, Vertex, Edge, Tile }

    /// <summary>Everything a session needs from the scene, created by HexhavenApp and passed in.</summary>
    public sealed class Services
    {
        public BoardView Board; public StormView Storm; public DiceView Dice; public ResourceFlyout Flyouts; public VfxFactory Vfx;
        public CameraRig Camera; public Picker Picker; public UiRoot Ui; public AudioService Audio;
        public SettingsStore Settings; public SaveStore Saves; public Tweens Tweens;
    }

    public sealed class GameSession
    {
        public GameEngine Engine { get; }
        public DisplayState Display { get; }          // what the UI shows right now (lags the engine while animations play)
        public int ViewerSeat { get; }                // whose private info the UI may show (see below)
        public InteractionMode Mode { get; }          // None, PlacePath, PlaceOutpost, PlaceKeep, PlaceSetupOutpost, PlaceSetupPath, MoveStorm, PlaceFreePath
        public event System.Action DisplayChanged;    // UI refresh trigger (coalesced once per frame)
        public event System.Action<string> Toast;     // user-facing messages

        public static GameSession Start(GameConfig config, Services services);
        public static GameSession Load(string saveText, Services services, out string error);
        public void Tick(float dt);                   // BotDriver + EventPlayer + autosave debounce
        public ApplyResult Submit(GameAction a);      // humans: validates, applies, enqueues events, autosave
        public void SetMode(InteractionMode m);       // validated against phase/legality; toggles
        public void OnBoardClick(PickKind kind, int id);
        public void End();                            // stops, deletes nothing (autosave persists unless GameOver)
    }
}
```

- **DisplayState** is a lightweight copy of everything the HUD shows (per-seat public counts, the viewer's hand and charters, bank, deck size, VP, awards, dice, phase, prompt, log lines). It is **advanced incrementally from each event's own data** as the EventPlayer finishes that event (e.g. `Produced` adds its Value to that seat's count and the viewer's hand; `Built` subtracts the cost and updates pieces/VP; redacted events adjust only public counts), because the engine is already at the end of the batch. When the queue becomes empty, DisplayState is **fully resynchronised from the engine** (and a debug assertion checks the incremental result matched). Board pieces are spawned by the EventPlayer as part of event playback (`Built` → drop-in animation), not by polling.
- **EventPlayer** holds a FIFO of `GameEvent`s (already redacted for `ViewerSeat`). Each event type maps to a playback coroutine-like routine (05/07 specify the animation and sound). Events of the same roll's production (`Produced`) play together. `Speed` = settings CPU speed for bot-originated events, ×1 for the viewer's own actions (but their own placements still animate). At Instant speed, events apply instantly (no animations) except the victory sequence. While the queue is non-empty, human input on the board is disabled except camera; UI buttons that would submit actions are disabled; clicking speeds up ×3.
- **BotDriver**: each frame, if the EventPlayer is idle and the first seat in `Engine.AwaitingInput()` that is a bot has waited its pacing delay (04 §5), call `BotBrain.Decide` and `Submit`. Trade responses: all bot targets get independent random delays; the proposer bot waits per 04 §3.8.
- **Human input routing**: if the first awaiting seat is human (or for Discard/RespondTrade any awaiting human), the UI shows the corresponding prompt/dialog for that human. In hot-seat (≥ 2 humans) the curtain (06 §4.1) appears first whenever that human differs from `ViewerSeat`; pressing Ready sets `ViewerSeat` to that human. With exactly one human, `ViewerSeat` is always that human. With zero humans (spectate), `ViewerSeat = -1` → the UI shows public info only plus a "Spectating" banner, and private log lines are redacted.
- **Order of simultaneous human prompts:** Discard: each affected human in clockwise order from Current; RespondTrade: each pending human target clockwise from proposer+1; bots respond concurrently with their delays.
- **Autosave**: after each successful `Submit` (human or bot), debounced (08 §3). Disabled for the rest of the session once any debug-overlay command has been used (09 §6).
- **Camera / post FX**: the runtime-created camera must get `UniversalAdditionalCameraData` (`GetComponent` or `AddComponent`) with `renderPostProcessing = true` and `antialiasing = SubpixelMorphologicalAntiAliasing`, inside `#if HEXHAVEN_URP`; otherwise the global Volume has no effect.
- **Loading**: to rebuild bot memories and the log after `SaveCodec.Read`, the session re-creates the game with `GameEngine.NewGame(config)` and applies the loaded action log one action at a time, feeding every resulting event (redacted per seat) to the bot memories and the log formatter, with no animations; then it asserts the hash equals the loaded engine's.
